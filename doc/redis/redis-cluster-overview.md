# Redis 集群方案总览与选型

> 主题边界：横向选型篇——只回答一个问题：**业务该用哪种 Redis 集群方案**。原生 Cluster 的分片、复制与故障转移细节见 [redis-cluster.md](./redis-cluster.md)，哨兵模式及其与 Cluster 的逐项对比见 [redis-sentinel.md](./redis-sentinel.md)。

---

## 1. 总述

目前国内 Redis 集群的主流方案主要分为三大类，其中 **Redis Cluster（官方原生集群）** 是目前生产环境中最主流的首选方案；此外还有已逐步退场的代理型历史方案。

| 方案 | 定位 | 一句话评价 |
|---|---|---|
| Redis Cluster | 官方原生分布式集群 | 生产主流首选，分片 + 高可用一体 |
| 云托管集群 | 企业级托管服务 | 花钱买运维，SLA 保证 |
| 主从 + Sentinel | 高可用（HA）方案 | 中小型系统标配，不解决分片 |
| Codis / Twemproxy | 代理型集群 | 历史方案，新项目已较少采用 |

## 2. 官方原生 Redis Cluster（生产主流首选）

Redis 3.0 之后官方推出的原生分布式集群方案，互联网和大型企业项目中最广泛采用的标准方案。

- **核心特点**：无中心化 P2P 架构，16384 个哈希槽（SLOT）动态分片，节点间 Gossip 协议通信
- **优势**：无代理层，性能损耗极低；原生支持自动故障转移和在线扩缩容（Resharding）
- **局限**：需要客户端支持集群协议（Smart Client）；不支持跨槽多 Key 操作
- **适用场景**：高并发、大数据量、需要水平扩展的生产环境

数据分片、主从复制、在线重新分片与自动故障转移的展开见 [redis-cluster.md](./redis-cluster.md)。

## 3. 云托管集群方案（企业级推荐）

阿里云、腾讯云等提供的托管版 Redis Cluster，底层基于原生 Cluster 或深度定制架构（如阿里云 Tair、腾讯 Tendis）。

- **优势**：自动故障转移、自动备份、一键扩容，具备 SLA 保证，大幅降低运维成本
- **局限**：成本相对较高，底层架构不可控
- **适用场景**：希望免去运维烦恼、追求高可用与稳定性的中大型企业

## 4. 主从复制 + Sentinel 哨兵（中小型系统标配）

1 个主节点 + N 个从节点，配合奇数个 Sentinel 节点进行监控与自动故障转移。

- **优势**：部署简单，成熟稳定，对客户端几乎零侵入
- **局限**：写操作仍是单点，无法突破单机内存上限
- **适用场景**：QPS 2~3 万以内、数据量几十 GB 以内、读多写少且不需横向扩展的业务

与 Cluster 的核心区别逐项对比见 [redis-sentinel.md](./redis-sentinel.md)。

## 5. 代理型集群（Codis / Twemproxy）（历史方案）

- **Twemproxy**：轻量级代理，静态分片，不支持动态扩缩容
- **Codis**：企业级动态分片代理，支持可视化 Dashboard，但组件复杂，新项目已较少采用

代理型方案的共性是在客户端与 Redis 之间加一层 Proxy 做分片路由：客户端零侵入，但多一跳网络转发带来性能损耗，且代理层自身需要高可用部署。原生 Cluster 成熟后，这类方案的历史使命已基本结束。

## 6. 选型总结

新建互联网项目或中大型系统，首选 **Redis Cluster** 或 **云托管 Redis 集群**；中小型业务或读多写少场景，**主从 + 哨兵** 依然是性价比最高的选择。
